# 使用指南

[English](usage.md) · [README](../README.zh-CN.md)

## 录制、驾驶与分段

1. 电脑运行 `scripts/connect.sh USER@ROBOT_HOST`。打开网页不会自动开始录制。
2. 录制为可选功能。需要保存数据时选择规格，再点击**开始录制**；采集与归档检查独立报告录制健康状态，不限制驾驶。
3. 启用手动驾驶，按住 W/A/S/D、方向键或按钮行驶，松开停车。空格和停车按钮会停止并锁定驾驶，但**不会结束录制**。
4. 按 **N** 或点击**下一段**标记新的路线／任务。可以填写下一段名称。普通分段不停车，不重启订阅。
5. 任务完成后点击**结束录制**。视频封装完成，剩余传感器分段归档，驾驶状态不变。等待完成后再关闭电脑端服务。

刷新网页不改变录制状态；只关闭浏览器，电脑端仍会继续记录。退出电脑端服务或断电会中断采集，不能当作正常结束。

前进、后退限速分别为 0–1 m/s，左右共用 0–2 rad/s 转向限速。保存限速先停车。自动探索另有独立的范围限制；手动驾驶不会自动避障。

## 数据与规格

点击**打开文件夹**查看 `~/Documents/Limo Console/recordings/SESSION/INSTANCE/`。每段包含 `manifest.json`、`frames.csv`、`camera.mp4`／`camera.mkv`／`frames/*.png`，以及 `sensors/*.mcap` 和校验凭据。会话目录中的 `configuration.json` 保存配置文本与哈希。控制台不会上传这些私人数据。

默认 640×480、10 fps，JPEG 传输、H.264 MP4 存储。FFV1 和 PNG 模式从 ROS 原始 RGB/BGR 像素生成无损 PNG 传输，并在电脑写入前核对像素哈希。“无损”相对于 ROS RGB 图像，不代表保存了传感器 Bayer 原始数据。更换分辨率后会确认实际输出尺寸，不通过放大图像冒充高分辨率。

新规格在停车后的下一段或下一次开始录制时应用。重新配置摄像头可能产生间隔，帧保留原始时间戳。启动时进行五秒帧率检查，明显不能持续的组合会被拒绝。设备支持的分辨率不等于每种组合都能持续达到目标帧率。

有发布且消息类型受支持的话题会被记录，包括原始 `/scan`、`/odom`、`/imu`、TF、相机标定、底盘状态、导航／地图、操作事件和控制门限输出。测试驱动没有提供物理转向角、车轮编码器读数，不能把角速度指令冒充实际转向角。

离线导出已完成的实例，不需要 ROS 或机器人连接：

```sh
.venv/bin/python -m harness.replay '/private/path/SESSION/INSTANCE' --export
```

导出里程计、差分加速度、IMU、请求／实际输出指令、操作事件 CSV 和验证 JSON；原始消息仍在 MCAP 中。IMU 加速度含重力和偏置，里程计加速度是速度差分。连续序号检查只覆盖录制器收到的消息，不能证明订阅前没有丢失。视频同时保留机器人单调时钟和 ROS 时间戳，不宣称硬件同步。

## 浏览、批量处理与下载

从控制台进入**数据**，或访问 `/data`。选择**整次录制**，可以统一查看本次全部分段、总帧数、已录视频时长、话题样本汇总、轨迹总览和速度／加速度历史。展开**单独查看分段**仍可访问原有单段视图。异常分段会保留提示，导出不会补回缺失的数据，也不会改变原始状态。

- **观看：**在横向播放列表中选择任意分段。勾选**连续播放**后，一段结束自动进入下一段，跳过没有相机画面的分段，最后一段结束后停止。H.264 使用浏览器视频控件，FFV1／PNG 使用解码帧预览，预览速度可能慢于采集速度；原文件的时间戳和质量保持不变。
- **批量处理：**结束本次录制后，点击**批量导出并校验全部分段**。每段生成自己的指标 CSV 和验证报告；某段失败会单独显示，其他分段继续处理。会话根目录下的 `exports/instances.csv`、`exports/validation.json` 汇总结果。图表为抽样显示，导出保留已接收指标；不会用虚构样本连接时间缺口和分段边界。
- **下载：**点击**打包整次录制 ZIP**包含全部分段目录、原始视频／图像、MCAP 与校验凭据、清单、已经生成的 CSV／地图，以及会话配置。如需 CSV／地图，请先批量导出再打包。点击**下载 ZIP**即可获得一个完整压缩包，源文件仍保留。单段 ZIP 和单文件下载也继续提供；**源文件位置**与打开按钮指向本机所选整次录制或分段的目录。
- **地图背景：**先导出含 `/map` 与 `map → odom` 变换的分段，再点击**显示地图背景**。图层使用最后记录的地图及对应变换投影里程计，不是经过 SLAM 优化的轨迹。在整次录制视图中，开启图层只显示当前所选分段，避免悄悄混用不同建图过程的坐标；隐藏地图可对比全部分段。缺图或缺坐标变换时禁用按钮，不假定已经对齐。

整次 ZIP 要求全部分段已关闭，包含打包开始时可用的文件；异常或仍等待归档的清单保持原有状态。批量导出和打包在同一个后台队列中进行。原文件不移动，ZIP 在 `recordings/.downloads/` 额外占用空间。

不连接机器人也可浏览已有记录：

```sh
.venv/bin/python -m companion.server --browse-only --data-dir '/path/to/recordings'
```

此模式提供相同的浏览、回放、导出和下载功能，没有驾驶连接。实时控制台已占用 18765 时，可用 `--port` 选择另一端口。

## 建图

停车时开始建图，再缓慢手动行驶，保持相邻观测重叠。建图和障碍判断使用雷达，相机预览／录制为可选功能，不是导航前提。建图扫描滤波只把孤立的远处异常点标为未知；原始雷达保留，碰撞判断仍使用原始数据。检查已知空地增长、定位和地图形状，不能只凭地图刷新判断精度。

保存时使用新名称。除 PGM/YAML 外，还保存 Cartographer `.pbstream` 或 SLAM Toolbox `.posegraph`／`.data` 状态。下载 ZIP 包含可移植的 PGM/YAML，SLAM 状态留在 `/control/maps/`。“保存并结束”仅在成功保存后停止 SLAM。自动探索终止时的应急地图是栅格快照，不是完整 SLAM 状态。

加载已有地图前，先保存并结束当前建图。在**自动导航与探索**中选择地图，填写机器人在该地图上的实际 X、Y 和朝向，再点击**加载地图并定位**。这只启动 AMCL，不发出驾驶目标。确认显示位置与实物一致后，再主动导航。通过建图引擎继续编辑 SLAM 状态属于高级操作；加载栅格定位并不等于自动恢复可编辑的 SLAM 会话。

自动探索通过 Nav2 检查车身净空和目标路径。没有安全可达边界时，可先进行有限角度的原地补扫：按当前雷达检查带余量的车身转动范围，线速度严格为零，观测朝向和位置变化，停车后再规划。转动范围有障碍、位置偏移、雷达过期或租约失效都会停止转向。不会以前进／后退作为补扫兜底；路径与转向范围均不可用时停车并说明原因，录制继续。默认探索上限为 120 秒、6 米、0.15 m/s；HTTP API 可设置更小范围。

## 异常恢复

- 录制异常会保留会话并显示缺口或故障，不改变驾驶状态；可用流继续记录。修复临时网络／存储问题后，点击**重试记录**检查恢复，不会新建会话。机器人或相机进程重启后，可能需要手动结束异常会话并重新开始。
- 下载完成不代表可以删除车端数据。只有文件大小与哈希正确、电脑文件及凭据已经持久化后才确认删除；不完整或不匹配的传输保留车端副本。
- 未完整封装的车端 MCAP 会保留并标记中断。私下复制到电脑后，可以恢复已完成且 CRC 正确的记录：

  ```sh
  .venv/bin/python -m harness.recover interrupted.partial.mcap recovered.mcap
  ```

  恢复不覆盖原件，也不会把不完整尾部标为完整。崩溃时尚未刷盘的数据可能无法恢复。分片 MP4 和未完成 CSV 会保留供检查；不要仅改文件名就认为完整。
- 摄像头过暗时先检查光线、遮挡和设备支持的曝光控制；提高保存质量不能补回没有采集到的光线。
- 静止维护模式会明确显示。删除 `/control/stationary-mode` 只允许之后主动启用驾驶，不会自动开车。
